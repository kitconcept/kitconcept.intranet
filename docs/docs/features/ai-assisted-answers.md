# AI-assisted Answers

:::{admonition} Feature summary
:class: warning

**Status:** v3 · **Beta (Provisional)** · Optional · **Audience:** all users ·
Requires Solr + an LLM service · **Interim source of truth** — canonical spec
will move to the intranet.
:::

## Summary

AI-assisted answers ("AI Overview" / "Ask AI") let a user ask a question in the
{doc}`Workspace search dialog <search>` and receive a **single-turn answer
grounded in intranet content**, with links to the source documents. Answers are
generated by a retrieval-augmented (RAG) pipeline over the same Solr corpus,
restricted to what the user is allowed to see and to the selected search scope.

It is an **optional beta** capability: it only appears when an administrator has
enabled it and connected an LLM service.

## Who it's for

- **All users**, as a faster way to get a grounded answer instead of scanning
  results — where the infrastructure is enabled.

## Capabilities

- An **"Ask AI"** action in the search dialog that returns a written answer.
- **Grounded** answers with a **Sources** list linking to the underlying
  documents.
- **Scope-aware** retrieval (current Workspace / another Workspace / everywhere).
- **Permission-trimmed** grounding — only content the user may access is used.

## Behaviour & rules

:::{admonition} For QA and product owners
:class: tip
This section is the behavioural spec. Treat each rule as a testable assertion.
:::

### How it's triggered and shown

- Normal typing produces live search suggestions; the AI answer is a **separate,
  explicit action** — an **"Ask AI"** button, shown only when the capability is
  available **and** the user has entered a query.
- The answer panel shows an **"AI Overview"** heading with a **Beta** badge, a
  loading state, the answer, and a **Sources** list (each source links to the
  parent document).
- A disclaimer is always shown: *"AI-generated answer. It may contain errors."*
- Editing the query or changing scope **resets** the answer (it was grounded in
  the previous question/scope).

### Grounding, scope, and isolation

- Retrieval is a **hybrid RAG** pipeline over the Solr corpus (vector similarity
  + keyword search, fused), and the answer is generated from the retrieved
  passages only. The model is instructed to **decline rather than invent** when
  the answer isn't in the sources, and to answer in the question's language.
- The selected **search scope** is applied as a real path restriction on
  retrieval — not cosmetic.
- **Permission trimming** is applied to retrieval on the server: the answer and
  its sources can only draw on content the current user is authorized to see.
  There is no cross-Workspace or unauthorized-content leakage; unpublished items
  must not appear.

### Enablement gate

- The "Ask AI" affordance appears only when the site reports the capability as
  **available**, which requires **both**:
  1. a **registry toggle** enabling RAG, and
  2. an **LLM service URL** configured (credentials live in the environment, not
     in site settings, so they aren't exported with configuration).
- This gate reflects **configuration presence, not live health**. If the LLM
  service is configured but unreachable, the button still shows and the failure
  surfaces at request time as a generic *"AI answer is currently unavailable"*
  message (technical detail is logged, not shown).

### Limits

- **Single-turn only.** A follow-up input exists in the design but is
  **disabled** — there is no multi-turn conversation.
- **Dialog-only.** AI answers are deliberately **not** offered on the classic
  search-results page (to avoid every search tying up backend workers).
- **No streaming.** The backend returns the whole answer at once; the "typing"
  effect in the UI is presentation only.
- The dialog's other filter chips (type/creator/date/status) are non-functional
  demo controls (see {doc}`search`), so they do **not** further constrain AI
  grounding even though the backend could accept such filters.

## Configuration / requirements

This is an **optional, infrastructure-dependent** feature. To enable it, an
administrator/operator must:

- Run **Solr** with the RAG chunk/vector schema and **reindex** the corpus for
  RAG (dedicated activate-and-reindex scripts / make targets exist).
- Turn on the **RAG registry toggle**.
- Provide an **LLM service URL** (and optional token / model overrides) via
  environment variables.

The default posture is **off** — nothing in the distribution enables RAG out of
the box.

:::{admonition} Beta — hold from firm public claims
:class: warning
This capability is classified **Optional / Provisional (beta)** in the v3 feature
set. Its enabled/disabled/unavailable/misconfigured states, answer and source
presentation, decline behavior, latency, and — critically — permission isolation
should be proven in a configured or deterministic test environment before it is
promised publicly. The backend plumbing is itself labelled beta in its source
package.
:::
